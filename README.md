# Экономика информатизации — решение экзаменационной задачи №5

Репозиторий содержит самостоятельное воспроизводимое решение задачи **«Расчёт стоимости разработки по COCOMO II»** для государственной информационной системы **«Единый портал поддержки предпринимателей»**.

Работа не ограничивается подстановкой чисел в формулу. В Notebook построена параметрическая модель стоимости разработки, а результат COCOMO II сопоставлен с методикой города Москвы из лекций №17 и №19. Все изменяемые исходные данные, коэффициенты и расчётные допущения вынесены в JSON.

## Содержание задачи

В работе рассчитываются:

- размер проекта по функциональным точкам и коэффициенту языка C#;
- размер проекта после учёта повторного использования для COCOMO II;
- показатель масштаба `B` по пяти scale-факторам;
- произведение корректирующих EM-факторов;
- трудоёмкость в человеко-месяцах;
- календарная длительность разработки;
- стоимость до НДС, НДС и стоимость с НДС;
- отдельный расчёт трудоёмкости и НМЦК по методике города Москвы;
- сравнение двух моделей и объяснение расхождений;
- чувствительность результата к ключевым параметрам.

## Ключевые результаты базового сценария

| Показатель | COCOMO II | Методика Москвы |
|---|---:|---:|
| Размер проекта | 19,44 KLOC | 24,30 РР |
| Трудоёмкость | 133,4 чел.-мес. | 142,7 чел.-мес. |
| Стоимость с НДС | около 44,0 млн руб. | около 27,2 млн руб. |

Для московского базового сценария использованы параметры из учебных материалов: базовая зарплата 78 300 руб., `Кпер = 1,064`, `К3 = 0,65` и рентабельность 5%. Рентабельность 10% показана отдельно как верхний сценарий; при ней НМЦК составляет около 28,5 млн руб. с НДС.

COCOMO II и методика Москвы не являются одной формулой с разными коэффициентами. Они используют разные правила определения размера, факторы трудоёмкости, стоимостные базы и структуру команды. Поэтому различия в итоговой стоимости интерпретируются экономически, а не считаются арифметической ошибкой.

## Важное решение по EM-факторам

В `data/task_05_cocomo_config.json` записаны все 17 EM-факторов COCOMO II. Если значение фактора равно `0`, он считается не заданным и исключается из произведения. В текущем сценарии `DOCU = 0` и `PVOL = 0`, поэтому используются 15 ненулевых факторов.

Это сделано намеренно: отсутствие данных не подменяется молчаливым предположением о среднем значении. При появлении подтверждённого значения его можно внести в JSON, после чего произведение EM и все последующие результаты пересчитаются автоматически.

## Установка и запуск

```bash
git clone https://github.com/Timoshkin-hash/eoi-e5.git
cd eoi-e5
python -m venv .venv
```

Для Git Bash на Windows:

```bash
source .venv/Scripts/activate
```

Для PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

Запуск Jupyter:

```bash
jupyter lab
```

Откройте `notebooks/task_05_cocomo_ii.ipynb` и выполните ячейки сверху вниз.

Для воспроизводимого запуска без ручного выполнения ячеек:

```bash
python -m jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.timeout=180 notebooks/task_05_cocomo_ii.ipynb
```

Для формирования HTML-отчёта:

```bash
python -m jupyter nbconvert --to html --no-input --output-dir reports --output task_05_report notebooks/task_05_cocomo_ii.ipynb
```

PDF-отчёт в репозиторий не включён: его можно получить из HTML через печать браузера (`Ctrl + P` → «Сохранить как PDF»).

## Как изменить модель

1. Откройте `data/task_05_cocomo_config.json`.
2. Измените нужное значение: функциональные точки, коэффициент повторного использования, scale-фактор, EM-фактор, стоимость человеко-месяца, МТ-фактор или параметр НМЦК.
3. Перезапустите Notebook с начала.
4. Все таблицы, итоговые значения и текстовые выводы будут пересчитаны.

В московском блоке отдельно редактируются `mt_factors`, `conversion_coefficient`, `planned_duration_months`, `roles`, `salary_base_rub`, `salary_share_coefficient` и `profitability_rate`.

## Методические границы

Значения МТ1–МТ7 и некоторые параметры состава команды не были заданы непосредственно в условии задачи, поэтому они вынесены в JSON и обозначены как сценарные допущения. Это позволяет заменить их подтверждёнными данными без переписывания Notebook.

TCO, ROI и NPV инвестиционного проекта в эту задачу не включены: условие требует оценить стоимость разработки и НМЦК, но не задаёт будущие выгоды, эксплуатационные денежные потоки и доходы.
